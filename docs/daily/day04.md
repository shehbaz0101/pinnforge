# Day 4

Adam training for the three Day 1 equations. `TrainConfig` is a pydantic model: equation id (the short CLI names work), interior / IC / BC counts, MLP hidden widths, epoch count, learning rate, loss weights `w_pde`, `w_ic`, and `w_bc`, seed, `device` (`cpu` only), a relative checkpoint directory, and a relative metrics path. Omitted `n_ic` and `n_bc` use the Day 2 per-equation defaults. The other defaults are a tiny harmonic problem: 32 interior points, hidden widths `(16, 16)`, 50 epochs, learning rate `1e-3`, and every weight `1`. `tanh` stays the activation because the residual needs a smooth second derivative.

`train_loop` builds the network with `mlp_from_spec` and draws one collocation batch with `sample_equation`. The batch is fixed for the run. Its seed is `TrainConfig.seed`, and `torch.manual_seed` uses that same seed before the weights are initialized. Every epoch evaluates that batch, appends one `metrics.jsonl` line, saves a checkpoint, and takes one Adam step. Re-drawing with `seed + epoch` would also be reproducible, but the logged loss would mix a new sample with the optimizer. This loop keeps the points fixed so `loss` and `loss_pde` can be compared from epoch 0 to the last epoch.

The scalar loss is `w_pde * MSE(residual) + w_ic * initial + w_bc * dirichlet`. `residual` is the Day 3 operator. The other two terms are `soft_penalty` (harmonic state or a Burgers profile, plus Dirichlet rows). Neumann and periodic faces stay unpenalized, so a periodic Burgers run records `loss_bc` of zero. Epoch 0 is the initial network, before any step. `--epochs 50` writes lines 0 through 50 and leaves the weights that produced line 50. Each line has `loss`, `loss_pde`, `loss_ic`, `loss_bc`, and `lr`. The component fields are the unweighted mean squares. `lr` is the Adam learning rate and is not scheduled.

Checkpoints are `torch.save` dicts with format `pinnforge.checkpoint.v1`, the epoch, the config, and the model `state_dict`. The loop writes `checkpoint.pt` (latest) and `epoch_XXXX.pt` under the checkpoint directory. Both the directory and the log path are relative and must stay inside the working directory. `load_checkpoint` rebuilds the MLP from the stored config and the built-in spec, loads the weights onto CPU, and returns the model in eval mode. Optimizer state is not stored. The file is for evaluation, not for resuming Adam.

`pinnforge train --equation harmonic --epochs 50 --seed 0` is the CPU demo. It needs the `ml` extra. Without torch it prints the same install hint as `pinnforge residual` and exits 1. `version`, `equations`, and `sample` still import with no torch.

Tests are marked `ml`. Default CI still runs `pytest -m "not ml"` without torch. The `cpu-torch` job runs the full suite, including a few-epoch harmonic run whose PDE or total loss drops from epoch 0, a checkpoint round-trip, and `TrainConfig` validation.
